    Centro de integração com o RD Station CRM

    A autenticação oficial é baseada em OAuth2 com access token e refresh token. Em produção, o fluxo deve ser tratado no backend, nunca diretamente no browser. [Source](https://developers.rdstation.com/reference/crm-v2-authentication)

    provider: mock
    • Usar o endpoint oficial de listagem de negociações para compor funil, forecast, perdas e filtros por etapa, owner, pipeline, motivo de perda e campos customizados. [Source](https://developers.rdstation.com/reference/crm-v2-list-deals)
    • Usar listagem de pipelines e etapas para refletir a estrutura oficial do funil da conta conectada. [Source](https://developers.rdstation.com/reference/crm-v2-list-pipelines) [Source](https://developers.rdstation.com/reference/crm-v2-list-stages-from-pipeline)
    • Usar webhooks de deal created, updated e deleted para sincronização incremental e quase em tempo real. [Source](https://developers.rdstation.com/reference/webhooks)

    Contrato de backend recomendado

    Rotas sugeridas para produção, protegendo segredos e centralizando a lógica de integração.

    GET /api/rdcrm/status GET /api/rdcrm/pipelines GET /api/rdcrm/stages?pipeline_id=:id GET /api/rdcrm/dashboard?unit=:slug&period=current_month GET /api/rdcrm/deals?unit=:slug&status=open GET /api/rdcrm/lost-reasons POST /api/rdcrm/sync GET /api/auth/rdcrm/connect GET /api/auth/rdcrm/callback POST /api/webhooks/rdcrm
    Versão HTML pronta para design review e handoff técnico. Para produção real, o front deve consumir APIs próprias que encapsulem OAuth2, renovação de token, paginação, filtros e webhooks do RD Station CRM. [Source](https://developers.rdstation.com/reference/crm-v2-authentication) [Source](https://developers.rdstation.com/reference/crm-v2-list-deals)
